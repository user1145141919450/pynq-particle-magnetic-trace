# golden-hdl-verify —— 黄金模型 + 逐位对拍（三层验证）

> **类型**：校验脚本 + 案例模板
> **适用场景**：定点算法 RTL（物理仿真、图像处理、轨迹/渲染、DMA 搬运）
> **来源**：本项目所有关键 IP 的验证实践——V3 束 17/17、粒子引擎 2000 子步、
> PL 检测 9/9 候选、画线 3523 像素、帧泵 0/921600。

---

## 1. 解决什么问题

RTL 调试最贵的一句话是“看起来差不多”。

- 定点数差 1 LSB，屏幕上可能看不出来，但物理长跑会累积成完全不同的终点；
- 画线少一个像素，人眼不一定发现，但逐位对拍会立刻指出第几笔；
- 帧泵的透视映射错一个像素，图像“看着对”，但和软件参考不一致；
- 仿真通过了、上板不对，可能是时序/复位/跨时钟域，而不是算法。

本技能把“算法正确性”变成**可定位的逐位比较**：先写 Python 黄金模型，
再让 RTL/PC/板三层都对着同一组期望值比；不一致就定位到具体下标。

---

## 2. 三层验证模型

```
              ┌─────────────────────────────┐
              │  Python 定点黄金模型         │
              │  （唯一期望值来源）          │
              └─────────────┬───────────────┘
                            │ 导出向量 / 期望文件
        ┌───────────────────┼───────────────────┐
        ▼                   ▼                   ▼
  ① RTL 仿真          ② PC 离线台架        ③ 上板逐位
  xsim + testbench    link_boot_selftest    v3_shoot / PE probe
  逐位比较            PC 489/板 488         map_detect / frame_pump
```

**原则**：
- 黄金模型用**定点**（或与 RTL 同口径的整数）实现，避免“浮点参考 vs 定点 RTL”的伪差异；
- 每层都输出“第几个元素不符、期望值、实际值”，而不是只报 PASS/FAIL；
- 三层的期望值来自同一份模型；任何一层改了算法，三层都要重跑。

---

## 3. 使用方法

### 3.1 写黄金模型

1. 用 Python/NumPy 实现与 RTL 同口径的定点算法；
2. 导出**确定性向量**：固定输入、固定初值、固定步数；
3. 输出格式建议：每行一个记录（`index value...`），便于 diff。

本项目的例子：
- `tools/v3_fixedpoint.py`：轨迹束定点物理；
- `tools/pe_fix.py`：粒子引擎物理；
- `tools/line_engine_check.py`：画线 DDA；
- `tools/v3_dump_tb.py`：把板上/仿真结果导出为文本。

### 3.2 写 testbench

- 用 `$readmemh`/`$fscanf` 读期望向量；
- DUT 输出逐拍/逐元素比较；
- 失败时打印 `index / expected / actual`，并 `$finish` 非零；
- 模板见 `templates/tb_golden_template.v`。

### 3.3 跑比较

```bash
# 通用文本比较（逐行/逐值，容差默认 0）
python scripts/golden_compare.py expected.txt actual.txt
python scripts/golden_compare.py expected.txt actual.txt --tol 0 --max-report 20

# 不用板子、不用 numpy：比较器自己的 7 条判据（差异/容差/进制/注释/字段数/记录数）
python scripts/golden_compare.py --selftest
```

退出码：0=完全一致；1=有差异；2=文件/格式错误。

### 3.4 上板对拍

- 板上脚本把 PL 结果导出为与黄金模型**同格式**的文本；
- 用 `golden_compare.py` 在 PC 上比；
- 对拍前先 `load_bit.py` + `pl_probe`，确认 bit 是本次构建；
- 每次构建后重跑，不沿用上一次的“绿”。

| 文件 | 用途 | 需要改什么 |
|---|---|---|
| `scripts/golden_compare.py` | 两个文本文件逐值比较，容差/最大报告数可调 | 分隔符、数值格式（如十六进制） |
| `templates/tb_golden_template.v` | 读期望向量 + 逐元素比较的 testbench 骨架 | DUT 端口、比较字段、时钟/复位 |

---

## 5. 失效条件

| 条件 | 后果 | 替代做法 |
|---|---|---|
| RTL 含浮点/非确定性调度 | 逐位比较无意义 | 改为容差比较 + 统计误差 |
| 黄金模型与 RTL 口径不同（取整/饱和） | 出现“伪差异” | 先对齐定点格式与边界口径 |
| 只测短跑 | 累积误差/溢出测不出 | 加长跑（本项目 2000 子步） |
| 只测正常路径 | 边界/越界漏测 | 加负坐标、越界、空输入、反压 |
| 上板沿用旧 bit | 比的是旧逻辑 | 每次 `load_bit` 后记录 bit md5 |

## 7. 来源失败（为什么值得做）

1. **粒子引擎 2000 子步**：短跑 400 步全过，长跑才暴露累积误差/越界；
   此后所有物理测试都至少 2000 子步。
2. **画线隔点丢线**：`fb_we` 电平 vs 写主 5~10 拍反压，导致“该笔落在 S_RESP 里丢掉”；
   逐笔对拍（3523 像素）才定位到具体像素。
3. **帧泵负坐标**：行表把两端先夹进源图再算斜率，留白区逆映射为负 →
   中心偏 3.7 源像素、左边缘 10 像素；逐像素对拍发现，改成 RTL 每像素钳位。
4. **`classify` 与 PL 候选口径**：只比“数量”会漏掉面积/质心差异；
   改成逐候选逐字段比较后，9/9 全等。

## 8. 迁移到别的题目

1. 先写黄金模型，再写 RTL（而不是反过来）；
2. 把“期望值”固化成文件，纳入版本控制；
3. testbench 只负责“读期望、逐元素比、打印第一处差异”；
4. PC 台架复用同一组期望值；
5. 上板脚本导出同格式，三层用同一个比较器；
6. 每次构建/改 RTL 后重跑三层，不沿用旧结果。

这套方法对“定点物理/图像处理/渲染/搬运”类 RTL 几乎零改动可用。
