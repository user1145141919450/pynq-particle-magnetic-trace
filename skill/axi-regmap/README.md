# axi-regmap —— 自定义 IP 的寄存器映射与自检

> **类型**：校验脚本 + 接口约定
> **适用场景**：自己写 AXI-Lite 寄存器核（加速器命令口、状态口、参数口）的 PYNQ / Zynq 项目
> **来源**：本项目驱动按过期注释写地址（把 `n_alive` 当 STATUS，误判 busy），
> 以及 2026-10-30 重建 BD 丢 IP 后**地址被顶掉**、驱动照旧跑通却读错寄存器。

**复制后必改（3 行）**

1. `--base 0x43B10000` → 你的 IP 基地址
2. `--fields "ctrl=0x00:0:0"` → 你的寄存器偏移 / 位域
3. `--walk 0x00:16` → 你的 RW 寄存器范围

---

## 1. 解决什么问题

自定义 IP 的“能不能用”通常死在三件小事上，而且**都不报错**：

1. **地址对不上**：BD 改了、`.hwh` 变了，驱动里的常量没变 —— 读到的是隔壁 IP 的寄存器，
   值“看起来像那么回事”，所以没人怀疑。
2. **位域错**：`ctrl[3]` 是软复位，代码里写成了 `ctrl[2]`；或者读的是 `{31:16}` 却当成 `{15:0}`。
3. **脉冲式完成位被漏掉**：PS 轮询间隔是微秒~毫秒级，RTL 里 `done` 只亮 1 拍 ——
   第一次 `poll` 时它早就灭了，软件永远等不到。正确做法是 RTL 里做成 **sticky（写 1 清）**。

`scripts/regmap.py` 把这三件事变成可执行的三条：

- **按名访问**：`--fields "ctrl=0x00:3:3,frames=0x08:31:0"`，读出来直接是数，写回去自动读-改-写；
- **走 1 自检**：对一段 RW 寄存器逐个写单比特再读回，用来区分“地址译码错 / 寄存器接错线 / 位宽少一根”；
- **带判据的等待**：`wait(off, mask, value, timeout)` 超时就报“等的是哪一位、最后读到什么”，
  而不是干等。

## 2. 使用方法

```bash
# 走 1：0x00 起 16 个 32 位寄存器
python3 scripts/regmap.py --base 0x43B10000 --walk 0x00:16

# 按名字 dump（字段表就写在命令行上，便于和 RTL 对照）
python3 scripts/regmap.py --base 0x43B10000 \
  --fields "ctrl=0x00:0:0,freeze=0x00:1:1,soft_rst=0x00:2:2,frames=0x08:31:0" --dump

# 不用板子：判据自己在 PC 上跑一遍
python3 scripts/regmap.py --selftest
```

在代码里用：

```python
from regmap import RegMap

r = RegMap(0x43B10000)
r.set('ctrl', 1)                     # 自动读-改-写，不动其它位
if not r.wait('status', 0x2, 0x2, timeout=0.5):
    raise TimeoutError(r.dump())     # 失败时打印全部字段，不是一句“超时”
```

**接口约定（写进你自己 IP 的 README）**：

| 约定 | 理由 |
|---|---|
| 每个 IP 至少一个**只读 ID 寄存器** | 下 bit 前的 `pl_probe` 靠它认“现在跑的是谁” |
| 完成位做成 **sticky，写 1 清** | 脉冲位在 PS 轮询下必漏 |
| 命令口与状态口**分开偏移** | 读状态不产生副作用，才能安全地反复 poll |
| 地址常量写在驱动里，并与 `.hwh` 对账 | 重建 BD 会悄悄改地址 |

## 3. 脚本说明

| 文件 | 用途 | 需要改什么 |
|---|---|---|
| `scripts/regmap.py` | 位域读写 / 走 1 自检 / 带判据的等待 | 无（基址与字段表从命令行给） |

退出码：0=全部通过；1=有失败；9=读不到（当“不知道”，不要当成通过）。

本队同类判据的位置：`software/pc/deploy_check.py` 的 `ADDR_EXPECT`（9 条）——
把驱动里的地址常量与 `.hwh` 里的 IP 实例逐一比对，构建后自动跑。

---

## 4. 失效条件

| 条件 | 后果 | 替代做法 |
|---|---|---|
| 寄存器有**读副作用**（读即清 / FIFO 弹出） | 走 1 会把状态读坏 | 跳过这些偏移；只对 RW 配置寄存器走 1 |
| 只读寄存器 | 走 1 必然“失败” | 字段表里标 RO，`--walk` 时排除 |
| 地址空间不连续 / 稀疏 | `--walk 0x00:16` 会打到未译码地址 | 用 `--fields` 按名访问，别整段扫 |
| 不是 AXI-Lite（AXI-Stream / BRAM 口） | 本工具不适用 | 用 BRAM 控制器或 DMA 的访问方式 |
| IP 有多套 AXI 接口（S_AXI + S_AXI_LITE） | 基址搞混 | 一个接口一张字段表，基址从 `.hwh` 抄 |

## 5. 已验证效果（本项目）

- `regmap.py --selftest`：**6/6**（含“卡死的位必须被抓到”“读-改-写不许动邻位”“等不到要报是哪一位”）；
- 本队驱动寄存器访问走的是 `fastmem.py`（`/dev/mem` mmap，15 µs/次 → 单字读降到亚微秒级），
  字段偏移以 RTL 译码为准；**通用封装 `regmap.py` 未在本队板上单独跑过**，这一条不藏着写；
- 地址层面的判据已上板长期使用：`ADDR_EXPECT` 9 条地址常量与 `.hwh` 逐 IP 比对，
  每次构建后由 `finish_build.py` / `deploy_check.py` 执行；
- 2026-11-01 的 16 粒 bit（`67412907`）上板后，`particle_pl.py probe` 的 P1–P6
  就是按位域读状态口判的，P6 实测“16 颗全存活 + `idx=16` 被越界防护拒”。

## 6. 来源失败（为什么值得做）

1. **注释与译码不一致**（见 `pitfalls/README.md` E4）：驱动按过期注释写寄存器地址，
   把 `n_alive` 当成 STATUS 读，于是“永远 busy”。修法只有一个：**以 RTL 译码 / `.hwh` 为准**，
   并把字段表做成单一来源。
2. **2026-10-30 重建 BD 丢 IP**：`pe_axi` / `map_detect_axi` 消失后地址被别的 IP 顶掉，
   构建 exit=0、台架绿；`ADDR_EXPECT` 对账才把它拦住。
3. **脉冲完成位**：早期 IP 的 `done` 只亮 1 拍，PS 轮询几乎必漏，
   现象是“偶尔成功、多数超时”；改成 sticky 之后同一份软件一次过。

---

## 7. 迁移到别的题目

1. 拷 `scripts/regmap.py` 到你的工程；
2. 从 `.hwh` 抄基址，从 RTL 译码抄字段表（不要从注释抄）；
3. 先跑 `--walk` 确认译码与位宽，再跑 `--fields --dump` 确认字段位置；
4. 把“只读 ID 寄存器 + sticky 完成位”两条约定写进你自己的 IP 文档；
5. 每次重建 BD 后跑一次 `--walk`，比读日志快。
