# 三分钟一镜到底 · 拍摄执行脚本（2026-10-31 晚）

> 目标：3 分钟内一镜到底，讲清"实物球 → 相机 → FPGA 并行算轨迹 → 屏幕实时判定"。
> 人物：**A = 操作手**（键盘+手机）、**B = 拍摄**（手持稳定器或三脚架）。
> 一镜到底允许剪头尾，中间不许剪；机位可以移动（这就是"一镜到底"好看的地方）。

---

## 0. 现场摆位（开拍前摆好，之后不再动）

```
                 ┌──────── 显示器（HDMI，1280x720）────────┐
                 │  屏幕朝左前方 45°，操作手要能看见        │
                 └───────────────────────────────────────┘
      ┌──────────────┐            ┌──────────┐
      │ OV5640 相机   │            │ 串口屏    │  ← 放在机位右手边，
      │ 垂直朝下 30cm │            │ 480x272  │     镜头能顺带带到
      └──────┬───────┘            └──────────┘
             │
      ┌──────▼─────────────────────────┐
      │        白纸场区（40×30cm）      │  ← 两盏台灯从左右斜照，
      │  球放这里；黑条/绿门/黑球在这摆  │     顶灯关掉，避免屏幕反光
      └────────────────────────────────┘
      ┌──────────┐   ┌──────────┐
      │ 键盘 P1   │   │ 手机 P2   │  ← 手机用支架立起来，屏幕朝镜头
      └──────────┘   └──────────┘
```

**灯**：关顶灯，两盏台灯左右 45° 斜照白纸。屏幕**斜 30°** 避开反光（否则整片反光，后期救不回来）。
**手机**：连板子 WiFi，页面提前打开、亮度最高、关自动锁屏。
**球**：红球/蓝球各一颗，先放在**画面外**（桌上），开场再用手放进去。

## 1. 逐秒脚本

| 时间 | 机位 / 动作 | 屏幕上会看到 | 台词（逐字念） |
|---|---|---|---|
| **0:00–0:15** | 全景，1.2m 外，慢慢推近 | 装置全貌 | 「这是一台用 FPGA 实时计算粒子轨迹的装置。桌面上这颗小球，代表一个带电粒子。」 |
| **0:15–0:30** | 镜头压低，俯拍白纸场区 | 空场区 + 橙色场区框 | 「相机每秒看它十五次，算出位置和速度；真正的核心计算不在这台电脑上，在这块 FPGA 里。」 |
| **0:30–0:40** | 手把红球放进场区 | 球被圈住 + 编号「1」 | 「球一进场，就被识别、编号。」 |
| **0:40–1:00** | 镜头摇到显示器（同框带一点实物） | 顶部 HUD：`P1 20° 400 px/s 控球1 ｜ P2 …`；绿色虚线瞄准线；17 个端点小点（绿=能进洞，灰=打回） | 「屏幕上这条绿线，是 FPGA 同时在算的 17 条射线：每条独立做磁场偏转、撞墙反弹、进洞判定。」 |
| **1:00–1:10** | 操作手按 **空格** 发射 | 球沿虚线飞出、撞墙反弹、进洞→绿闪 | 「一次算完 6.7 毫秒；同样的算法用 CPU 串行跑要 1.6 秒——**242 倍**。」 |
| **1:10–1:20** | 镜头摇到键盘（手部特写） | — | 「换一种磁场会怎样？按 Q 改磁场。」 |
| **1:20–1:45** | A 操作：`Q` → `A/D` 选块 → **`E` 确认** → `W/S` 改方向 → **`E` 确认** → 数字键输入强度 → **`E` 确认** | 选中的块高亮 → 方向符号 ⊙/⊗ 切换 → 块上标 `B+0.7` | 「三步确认：选哪一块、往哪个方向、强度多少。没确认之前不算数。」 |
| **1:45–1:55** | 镜头回到屏幕 | 瞄准虚线**跟着弯了** | 「磁场一改，同一条轨迹立刻弯向另一边——这就是物理在跑，不是画上去的。」 |
| **1:55–2:10** | A：`V` 加障碍 → 手把黑条放到场区 → **`E`** | 黑条被黄框框住（黄框=真正的碰撞边界） | 「还能现场加障碍。黄框就是球真正会反弹的边界。」 |
| **2:10–2:25** | A：`G` 加传送门 → 放两扇绿门 → **`E`** | 两扇绿门 + 瞄准虚线在门处**断开** | 「传送门：线在这里断开，因为下一帧它从另一扇门出来。」 |
| **2:25–2:40** | A：`C` 加洞口 → 黑球贴到场区边 → **`E`** | 洞口绿线出现 + 30 秒倒计时 | 「洞口也能现场加——贴哪个边就在哪个边开洞。」 |
| **2:40–2:52** | 镜头横移，同框拍**手机**：手指拖角度滑条 → 点「发 射」 | 手机页面 + 屏幕同时变化 | 「手机就是手柄：两个人一台手机，一人一半。」 |
| **2:52–3:00** | 慢慢拉回全景 | 整机 | 「判定结果和黄金模型逐位一致，17 路，一条不差。」 |

## 2. 每个动作的"成功标志"（看一眼就知道过没过）

| 动作 | 成功标志 |
|---|---|
| 球进场 | 屏幕上出现**彩色圆圈 + 数字**（1、2…） |
| 瞄准 | 出现**一条虚线**（P1 绿 / P2 紫）+ 末端十几个小点 |
| 发射 | 虚线消失、球开始飞；进球=绿圈闪光 |
| 改磁场 | 块上的 `B+0.4` 变成新数值；虚线曲率明显变化 |
| 加障碍 | 黑条外出现**黄框**（贴着黑条） |
| 传送门 | 两扇门之间瞄准线**断开** |
| 加洞口 | 场区边上出现**粗绿线** + 屏底倒计时 |
| 手机发射 | 手机上角度数字变化，屏幕同帧跟着变 |

## 3. 翻车预案（一镜到底专用）

| 现象 | 当场怎么办 |
|---|---|
| 球没识别 / 圈不出现 | 把球**拿起再放下**一次（别停在贴边）；镜头保持不动，嘴上继续讲 |
| 画面卡/花 | 不要停，镜头转向手机或串口屏，讲"两套人机界面" |
| 改磁场按了没反应 | 大概率是**没确认**——再按一次 `E`；屏幕上三步提示会告诉你卡在哪步 |
| 真卡死（黑屏/不动） | 对镜头说一句"我们重来一镜"，A 停游戏重启（30 秒） |
| 时间超了 | **砍掉 2:10–2:25 传送门**那一段，其余不动 |

## 4. 开拍前 40 分钟准备（我这边跑）

```bash
# 1) 冷启动后（最稳，HDMI 相位问题只有冷启动能根治）
python3 wp_health.py                     # 文件+import 探针
python3 pl_probe.py                      # 看 PL 现况
python3 load_bit.py                      # 唯一允许的下 bit 入口
# 2) 相机链路自检：地图自检 100%、errs=0、14.7fps
# 3) 打进第 2 局局前（商店/选购/布置镜头能自然出现）
# 4) 定妆照一张留档： ./v3_shoot.sh --cam   （17/17 逐位）
```

**A 操作手的检查**：键盘 P1 键位背熟（`W/S` 角度、`A/D` 速度、`空格` 发射、`Z/X` 选球、`Q` 改磁场、`V` 障碍、`G` 门、`C` 洞、`E` 确认、`ESC` 退一步）。

## 5. 台词总时长核对

全部台词念一遍约 **2 分 20 秒**（正常语速 4~5 字/秒），留 40 秒给动作等待——**刚好 3 分钟**。
如果排练时超时：先删 2:10–2:25 传送门，再删 1:55–2:10 障碍。
